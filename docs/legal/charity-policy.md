# 公益模块规则（草案）

核心目标：保持“公益为主”的主旨，但在中国大陆/美国等地区避免被认定为未经资质的公开募捐平台。

## 1. 公益与支持/打赏/交易必须分离

- **公益（Charity）**：面向合规慈善组织/具备资质主体的项目，强调披露与合规。\n- **支持/打赏（Support/Tips）**：对创作者/项目的赞助或购买回报，不宣称“捐款/慈善”。\n- **交易（Marketplace）**：商品/作品买卖。\n
## 2. 中国大陆建议的首发策略（风险最低）

- 不开放“个人发起公开募捐”。\n- 仅展示与运营已验资的机构项目。\n- 捐赠通道由**具备资质的慈善组织/合规平台**承接（可做嵌入式H5/SDK，做到“流程在App内完成，但平台不经手资金”）。\n
## 3. 费用与披露

- 必须显著披露：是否收取技术服务费、支付手续费、平台运营费用。\n- 项目必须提供：资质信息、资金用途、进度更新、凭证/审计材料（如有）。\n
## 4. 反诈骗与审核

- 对公益项目更严格审核：主体资质、联系人、项目真实性材料。\n- 对敏感词（虚拟币、私钥、二维码收款等）强拦截。\n
